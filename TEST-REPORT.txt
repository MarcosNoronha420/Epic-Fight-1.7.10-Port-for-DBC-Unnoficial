2.2.0-RC2 STRUCTURAL CHANGES
1. CombatHitResolver
   - ColliderDefinition is executable runtime hit data instead of unused metadata.
   - Sweeps authored OBB volume using collider.count samples across the current tick transform.
   - Uses per-target × hit-window identity memory, allowing one attack window to hit multiple entities without re-hitting the same entity in that window.
   - Keeps StateSpectrum/action clock as the timing authority and delegates final damage through the existing Minecraft/DBC attack path.
   - RC1 collider anchoring is interpolated player-view space. Joint-local Tool_R/Hand_R collider sampling is the next parity step and is NOT claimed complete here.

2. CombatController decomposition
   - CombatGuardRuntime owns DBC guard state, two-tick release hysteresis and guard-hit reactions.
   - AttackCadenceTracker owns recent click cadence and source-style fast-fist playback scaling.
   - CombatController remains the orchestrator for action selection/clock and dash input edge handling in this RC.

3. DBC/JRMCore state lifetime
   - DbcClientState.TickSnapshot caches stable per-tick blocking/Ki/floating/ground/flying/speed state.
   - Live JBRA render evidence remains render-sensitive.
   - visualRevision invalidates same-tick pose reuse when flight presentation changes during rendering.

4. Animator / pose reuse
   - PoseEngine suppresses exact duplicate final-pose composition for the same player/tick/partial/render state.
   - LayeredAnimator exposes poseSerial for downstream geometry caches.

5. Skinning hot paths
   - SkinnedPlayerRenderer caches skinning by poseSerial.
   - The skin matrix array is captured once per render; normal emission no longer asks PoseEngine.skinMatrices() from inside geometry loops.
   - ModelRendererSkinHook measures the live native JBRA skin dispatch when profiling is enabled.

6. Diagnostics
   - RuntimeProfiler is opt-in with JVM flag -Depicfight1710.profiler=true.
   - Slots: Animator, collider, DBC-state, JBRA-skin, first-person and combat.
   - No animation-rate reduction or visual simplification is used as an optimization.
